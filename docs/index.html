1. Why calibrate a camera?

A camera turns 3D rays into 2D pixels, but two things distort that mapping:

  • Intrinsics: the focal length and optical centre, which define how 3D points land on the image.
  • Lens distortion: real lenses bend straight lines, especially near the image edges.

Anything that measures from images (distances, angles, marker pose, visual odometry, SLAM, 3D reconstruction) is biased until these are known. Calibration estimates them once per camera, resolution and focus setting.

2. The camera model

OpenCV uses the pinhole model. A 3D point (X, Y, Z) in the camera frame projects to pixel (u, v):

u = fx * (X / Z) + cx
v = fy * (Y / Z) + cy

    | fx  0  cx |
K = |  0 fy  cy |     (camera matrix)
    |  0  0   1 |
ParameterMeaning
fx, fyFocal length in pixels. Usually almost equal.
cx, cyPrincipal point, where the optical axis meets the image. Near the image centre.

Each image of the calibration board also has its own extrinsics (rotation and translation of the board relative to the camera). They are solved during calibration but are not needed afterwards. Only K and the distortion coefficients are kept.

3. Lens distortion

With normalised coordinates x = X/Z, y = Y/Z and r² = x² + y²:

# radial: straight lines bow outward (barrel) or inward (pincushion)
x_d = x * (1 + k1*r^2 + k2*r^4 + k3*r^6)
y_d = y * (1 + k1*r^2 + k2*r^4 + k3*r^6)

# tangential: lens not perfectly parallel to the sensor
x_d = x + 2*p1*x*y + p2*(r^2 + 2*x^2)
y_d = y + p1*(r^2 + 2*y^2) + 2*p2*x*y

OpenCV returns [k1, k2, p1, p2, k3]. On typical webcams k1 is negative (barrel distortion) and p1, p2 are close to zero.

4. How calibration works

OpenCV implements Zhang's method:

  1. Show the camera a flat target with known geometry from many viewpoints.
  2. Detect the target's corners in each image. Their 3D positions on the board are known (the board plane is Z = 0, and the spacing is the printed square size).
  3. Each view gives a homography from the board plane to the image, which constrains K. Three or more different orientations let K be solved in closed form.
  4. That gives an initial guess for K, the distortion, and every view's pose.
  5. Everything is refined together with non-linear least squares (Levenberg-Marquardt), minimising the reprojection error: the pixel distance between detected corners and the corners obtained by projecting the known 3D points through the current model.
Why many angles? If every view is frontal, focal length and distance are ambiguous. Tilted views remove the ambiguity, and views that reach the image corners are what constrain distortion.

5. Calibration targets compared

TargetProsCons
CheckerboardSimple, accurate sub-pixel corners, built into OpenCVWhole board must be visible in every image, so edges are poorly covered. No IDs, no partial views
Circle gridAccurate centres, tolerant of blurPerspective bias on circle centres; needs the whole grid visible
ArUco boardUnique IDs, works with partial views and occlusionMarker corners are less accurate than checkerboard corners
ChArUco (used here)Partial views allowed, every corner has an ID, sub-pixel accurate, robust to occlusionNeeds OpenCV contrib (aruco module)
AprilGridStandard in Kalibr; great for multi-camera and camera-IMU setupsNeeds separate tooling

Why ChArUco? Each corner carries an ID, so the board does not have to be fully in view. You can push it into the frame corners, which is where distortion information lives, and a hand or glare covering part of the board does no harm.

6. The toolkit: workflow

The repository is driven by a single config.py. Every script reads it, so changing camera, resolution or board size only needs one edit.

  1. ConfigureSet camera index, resolution and board size in config.py.
  2. Generate the boardgenerate_charuco.py creates a PDF that prints at the exact square size.
  3. Capture imagescapture_images.py shows live corner detection and only saves good frames.
  4. Calibratecalibrate.py solves for K and distortion and reports the error per image.
  5. Validatevalidate_calibration.py shows original vs undistorted and detected vs reprojected corners.
  6. Use itundistort.py and capture_undistorted.py process images, folders, videos, or live camera.

7. Quick start

git clone https://github.com/Vihaan30g/webcam-calibration-opencv.git
cd webcam-calibration-opencv
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python3 scripts/generate_charuco.py        # print data/boards/charuco_board.pdf at 100%
python3 scripts/capture_images.py          # 's' to save, 'q' to quit
python3 scripts/calibrate.py --visualize
python3 scripts/validate_calibration.py --save
Print at 100% scale ("Actual size", never "fit to page"), mount the board on something rigid and flat, and measure one square with a ruler. If it is not 30 mm, update SQUARE_LENGTH and MARKER_LENGTH in config.py.

Capturing a good image set (25 to 40 images)

  • Cover every region of the frame, including the corners and edges.
  • Tilt the board up to about 45 degrees in different directions.
  • Vary the distance: near, medium and far.
  • Hold still to avoid blur, and keep the lighting even.
  • Do not change zoom or focus during the session. Lock autofocus if you can.

Full step-by-step instructions are in the repository README.

8. Reading the results

RMS reprojection errorQuality
< 0.5 pxExcellent
0.5 to 1.0 pxGood
1.0 to 2.0 pxAcceptable
> 2.0 pxRecapture

A low error alone does not prove accuracy, so also check:

  • fx and fy should be close to each other.
  • cx, cy should be near width/2, height/2.
  • A very large k3 (magnitude above about 5) suggests overfitting. Set FIX_K3 = True in config.py.
  • In the validation window, straight lines should come out straight and the green and red points should overlap.
  • Delete images with clearly higher per-image error and recalibrate.

9. Using the calibration

import cv2, numpy as np, yaml

with open("data/calibration_results/calibration.yaml") as f:
    cal = yaml.safe_load(f)

K    = np.array(cal["camera_matrix"]["data"]).reshape(3, 3)
dist = np.array(cal["distortion_coefficients"]["data"]).reshape(1, -1)
size = (cal["image_width"], cal["image_height"])

new_K, roi = cv2.getOptimalNewCameraMatrix(K, dist, size, alpha=0)
map1, map2 = cv2.initUndistortRectifyMap(K, dist, None, new_K, size, cv2.CV_16SC2)

und = cv2.remap(cv2.imread("my_image.png"), map1, map2, cv2.INTER_LINEAR)
x, y, w, h = roi
und = und[y:y+h, x:x+w]          # crop black borders
  • Pose estimation (ArUco, AprilTag, solvePnP): use K and dist on raw images, or new_K with zero distortion on undistorted ones. Never undistort twice.
  • ROS 2 CameraInfo: k = the nine values of K, d = [k1, k2, p1, p2, k3], distortion_model = "plumb_bob".
  • Resolution: the calibration is valid only at the resolution it was captured at. The scripts check this and stop on a mismatch.

10. Limits and next steps

  • Recalibrate if you change focus, zoom, resolution mode, or if the lens is knocked.
  • Intrinsics do not depend on the true square size, but any metric distance does, so measure the printed board.
  • For wide-angle and fisheye lenses (about 120 degrees or more), use OpenCV's cv2.fisheye model instead.
  • This toolkit calibrates a single camera. Stereo, hand-eye and camera-IMU calibration are the natural next steps.
